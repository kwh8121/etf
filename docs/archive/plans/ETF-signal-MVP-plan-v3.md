# ETF-signal MVP v3 개선안

## 1. 결론과 필수 전제

**MVP의 모든 외부 투자·시장 데이터는 키움과 KRX가 제공하는 데이터로 제한한다.** 다른 데이터 제공업체, 운용사 사이트, 기업 공시 사이트, 뉴스, 유료 리서치를 필수 의존성으로 추가하지 않는다. 분류·분배금·기업행동 자료도 키움·KRX에서 확보할 수 있을 때만 사용한다.
궁극적인 목적은 ETF 매매의 수익성 확보다. 이 목적에 맞춰 MVP는 **관측 가능한 신호가 실행 가능한 가격과 비용 조건에서 투자 판단에 추가 가치를 주는지 검증하는 시스템**으로 설계한다. 현 자료로 측정 가능한 가격성과와, 분배금·세금 등을 포함한 실제 투자 순성과는 구분한다.
**권장 결정:** KRX 일별 수집·저장·알림 구조는 유지한다. 가격·거래대금 중심의 Scanner와 전향적 가상 추적을 핵심 MVP로 삼고, 순설정 추정 신호는 계산 오류를 수정한 뒤 실험 기능으로 분리한다. 외부 자료가 있어야 가능한 기능 때문에 전체 MVP를 중단하지 않는다.

### 전제의 적용 범위

*   허용: 키움·KRX 원천 응답, 그 응답에서 계산한 파생지표, 내부 수집 로그, 전략 설정, 사용자 승인·기각 기록.
    
*   비용·포지션·보유기간 등의 전략 설정은 실제 관측 데이터와 구분해 `assumption`으로 저장한다.
    
*   금지: 이름만으로 확정한 상품 분류, 외부에서 보충한 구성종목·분배금·펀더멘털을 MVP 필수 입력으로 사용하는 설계, 누락 데이터를 임의로 만들어 채우는 방식.
    
*   동일 제공기관의 추가 API는 사용할 수 있다. 다만 명세·권한·실제 응답을 확인하기 전에는 해당 데이터가 확보된 것으로 간주하지 않는다.
    
*   기본 운영 가정: 일별 신호, 수일~수주 가상 보유, 수동 승인, 자동 주문 제외.

## 4. 구현 전 반드시 수정할 오류

### 4.1 분할 필터

현재 SQL은 `좌수비 × NAV비`가 0.95~1.05일 때 좌수 증가분을 유입으로 합산한다. 분할 시 이 곱이 1에 가까워지므로 분할이 그대로 통과한다. 반대로 큰 실제 설정은 제외될 수 있다.
계산 예시이며 실제 시장 데이터는 아니다.
| 상황 | 좌수 | NAV | 비율의 곱 | 기존 결과 |
| --- | --- | --- | --- | --- |
| 10배 분할 | 100 → 1,000 | 100 → 10 | 1.00 | 가짜 유입 9,000 합산 |
| 실제 설정 10% | 100 → 110 | 100 → 100 | 1.10 | 실제 설정 추정액 제외 |

**키움·KRX 한정 대응:**

1.  해당 제공기관에서 분할·병합 이력을 확인할 수 있으면 조정배수를 적용한다.
    
2.  확인할 수 없으면 좌수의 급격한 비율 변화, 반대 방향 NAV 변화, 순자산의 연속성 등으로 이상 의심 플래그를 만든다.
    
3.  휴리스틱만으로 분할 여부를 확정하지 않는다. 의심 구간의 순설정 신호는 순위에서 제외한다.
    
4.  의심 징후가 없다는 사실도 기업행동 부재의 증명으로 취급하지 않는다. 지표 명칭과 상태는 계속 ‘순설정 추정·실험용’으로 유지한다.
    
5.  신뢰성 있는 보정이 불가능하면 순설정 기능만 비활성화하고 핵심 Scanner를 운영한다.
    

공식 조정배수가 확인된 경우의 계산식:
`일별 순설정 추정액 = (당일 좌수 − 전일 좌수 × 당일 적용 분할배수) × 당일 NAV`
이 값은 실제 현금 입금액이나 최종 투자자의 매수 의도를 확정하는 값으로 표시하지 않는다.

### 4.2 거래일·공란 응답

KRX 실측 보고서는 HTTP 200과 다수의 행이 있어도 핵심 숫자가 전부 공란인 응답을 기록했다. 빈 배열·공란을 곧바로 휴장으로 처리하지 않는다.

*   호출 전에 유효한 달력 날짜를 검사한다.
    
*   날짜 결속, 중복 코드, 필수 필드, 숫자 형식을 검증한다.
    
*   키움·KRX에서 확인 가능한 거래일 정보가 있으면 사용한다.
    
*   확인할 수 없으면 `unknown_session` 또는 `pending`으로 남기고 재조회한다. 응답만으로 공식 휴장을 확정하지 않는다.
    
*   거래일임이 확인된 날짜의 데이터 미확보는 `missing`으로 기록한다.
    
*   거래일 연속성을 확인할 수 없는 창은 신호 계산을 보류한다. 결손을 건너뛴 행 수를 임의로 ‘최근 20거래일’이라고 부르지 않는다.
    

### 4.3 관측·누적·신호 정의

*   `obs_days`: 기준일까지 관측된 행만 집계. 미래 데이터 금지.
    
*   `lag`: 결측 행을 먼저 제거해 여러 거래일의 변화를 하루 변화로 계산하지 않음.
    
*   `flow_5d`: 유효한 일별 변화 5개를 요구. 일부 결측을 무시한 합계를 완전한 5일 지표로 표시하지 않음.
    
*   `avg20`: 당일 제외, 최근 20거래일의 유효한 거래대금 20개 확인.
    
*   유입과 유출은 별도 신호. 절댓값으로 유입 순위를 만들지 않음.
    
*   `first_seen`과 `listing_date` 분리. 최초 일괄 수집 종목을 신규 상장으로 알리지 않음.
    
*   5일 누적 상위의 연속 등장은 연속 유입과 구분. 일별 양수 유입 일수와 연속 일수를 별도 계산.
    

## 5. 권장 MVP 구성

### P0 — 핵심 기능

**A. 재현 가능한 일별 수집**
KRX를 중심으로 일별 데이터를 저장하고, 키움으로 현재 상장일·상태와 검증 가능한 표본을 보완한다. 원본·해시·수집 시각·변환 버전을 보존한다.
**B. 가격·거래대금 Scanner**

*   가격 변화: 단기·중기 가격수익률, 추세 변화, 확인 가능한 비교군 내 상대강도.
    
*   거래 활동: 당일 거래대금/직전 20거래일 평균, 거래대금 하한.
    
*   추격 위험 참고값: 최근 상승 폭, 최근 고점 대비 거리, 변동성.
    
*   신규 상장: 키움의 실제 상장일과 신규 관측 여부를 구분해 별도 표시.
    

기준 기간·임계값은 사전 설정한 실험값이다. 성과를 보면서 후보 수를 맞추는 방식으로 매일 조정하지 않는다. 분배금·기업행동이 미조정된 가격지표라는 한계를 필드와 화면에 표시하고, 관측 가능한 이상은 격리한다.
**C. 전향적 가상 추적**
매일 발생한 전체 신호와 제외 사유를 저장한다. 알림은 동일·유사 노출의 중복을 확인할 수 있는 범위에서 정리한 최대 3개와 최우선 검토 1개로 제한한다. 분류가 불명확하면 중복 제거를 완료했다고 표시하지 않는다. 적격 후보가 없으면 0개를 허용한다.

### P1 — 실험 기능

순설정 추정, 가격/NAV 괴리 참고값, 선택 후보의 장중 유동성 관측.
괴리율은 NAV와 가격의 평가 시점 차이로 왜곡될 수 있으므로, 시점 정합성이 확인되지 않은 값으로 저평가나 차익거래 기회를 확정하지 않는다.

### MVP 제외

펀더멘털 기반 과매도 판정, 수출·수주·실적 가이던스 Radar, 외부 뉴스 Catalyst, 구성종목 전체 자동 분석, 무검증 과거 전체시장 총수익률, 자동 주문.

## 6. 수익성 검증 설계

### 6.1 비교 실험

동일한 가용 종목 집합·체결 시점·비용 가정에서 다음을 비교한다.

1.  **기준 전략:** 단순 가격 모멘텀.
    
2.  **핵심 전략:** 가격 모멘텀 + 거래대금 변화.
    
3.  **실험 전략:** 핵심 전략 + 순설정 추정. 순설정 검증을 통과한 범위에서만 실행.
    

필터를 추가했을 때 별도 평가 기간의 성과·낙폭·회전율이 개선되는지 측정한다. 신호가 겹친다는 이유만으로 더 강한 투자 확신을 부여하지 않는다. 임계값을 학습한 구간과 평가 구간을 분리하고, 같은 종목·테마의 반복 신호를 독립 표본처럼 과대 계산하지 않는다.

### 6.2 성과 명칭과 범위

| 지표 | MVP 처리 |
| --- | --- |
| 가상 체결 기준 가격수익률 | 측정. 분배금 제외 여부를 명시 |
| 가정 거래비용 차감 가격성과 | 측정. 비용 시나리오·가정 버전 표시 |
| 포트폴리오 가격기준 최대낙폭·회전율 | 현금·동시 보유·중복 진입을 반영해 측정 |
| 가격기준 전략 간 성과 차이 | 동일 조건 비교. 이를 분배금 포함 알파로 부르지 않음 |
| 분배금 포함 총수익률 | 키움·KRX의 이력 확보·계산 검증 전 미산출 |
| 세후 순수익·실거래 수익 | 필요한 데이터가 확보되지 않은 단계에서는 미산출 |

가격성과는 분배금 지급 정책에 따라 비교가 왜곡될 수 있다. 알려진 분배금 자료가 없다면 해당 한계를 제거했다고 주장하지 않는다. 알 수 없는 과거 분배락을 추정해 보정하거나 결과를 본 뒤 특정 구간을 임의 제거하지 않는다.

### 6.3 체결·보유 규칙

*   장 마감 후 신호는 당일 종가 체결 금지.
    
*   기본 가상 체결은 신호 확정 후 다음 거래 가능한 세션의 시가와 사전 비용 가정으로 계산. 실제 체결 보장으로 표시하지 않음.
    
*   사용자 승인을 거치는 경우 승인 시각 이후의 가격만 사용.
    
*   기본 평가 보유기간 1개를 사전 고정하고, 보조 기간의 결과는 민감도 분석으로 구분.
    
*   최대 보유 수, 종목별·총노출 한도, 재진입·추가매수·청산 규칙을 전략 설정으로 고정.
    
*   매수·매도 스프레드와 슬리피지는 실제 관측값 또는 명시적 가정을 사용. 비용 모델에 이미 포함한 항목은 중복 차감하지 않음.
    
*   체결 지연, 비용 확대, 미체결 조건에서도 성과가 유지되는지 시험.
    
*   일봉만으로 장중 손절·익절의 선후를 확정하지 않음. 초기에는 관측 가능한 시점에 기반한 단순 청산 규칙을 우선.
    

### 6.4 과거 데이터와 전향적 평가

25영업일 백필은 초기 지표 준비용이다. 긴 과거 자료가 확보되면 탐색 실험에 활용하되, 제공 시작일 표기만으로 전체 기간의 완결성을 확정하지 않는다.
현재 키움 목록을 과거 전체시장 목록으로 사용하지 않는다. 과거 종목 상태·기업행동·분배금이 불완전하면 분석 범위와 누락을 표시한다. 수집 시작 이후 보존한 시점별 데이터에 따른 전향적 가상 추적을 핵심 평가로 삼는다.
20영업일은 운영 점검 구간이다. 이를 넘겼다는 이유로 실거래를 승인하지 않는다. 가격 신호의 예비 유용성이 확인되더라도, 미확보 분배금·세금·상품 구조가 실제 판단을 바꿀 수 있으면 최종 수익성 판정을 유보한다.

## 7. 최소 스키마·운영 개선

### 데이터 및 연구 기록

*   `etf_daily`: 기존 필드 + 시가·고가·저가, 원천, 수집 시각, 데이터 버전, 품질 상태.
    
*   `etf_master_snapshot`: 관측 시점, 원천 코드, 실제 상장일, 확인 가능한 상태·상품 분류. 불명 항목은 null로 유지.
    
*   `collection_ledger`: `ok / pending / incomplete / missing / confirmed_holiday / unknown_session`, 오류와 재시도 이력.
    
*   `signal_run` 및 `signal_daily`: 신호 생성 시각, 전략 버전, 입력 버전, 전체 후보·제외 사유, 실험/관측 상태.
    
*   `paper_trade` 및 포트폴리오 평가: 진입·청산 시각과 가격, 수량, 비용 가정, 현금·잔고, 가격기준 손익.
    
*   `decision_log`: 승인·기각·보류 이유와 시각. 외부 데이터의 우회 입력 경로로 사용하지 않음.
    

### 운영 원칙

*   `(날짜, 코드)` PK 외에 신호 실행·발송 중복 방지 키를 둔다.
    
*   원본은 `raw/날짜/수집시각_해시.json.gz`로 버전별 보존한다.
    
*   재수집으로 바뀐 데이터와 당시 발송 신호를 함께 보존한다.
    
*   수집 실패·실행 누락은 완료 기한 이후 감시한다. 세션 상태가 불명확하면 ‘휴장’ 대신 ‘데이터 상태 미확정’으로 알린다.
    
*   KRX 호출 환경이 막히면 수집 실행 위치를 먼저 교체한다. 이를 이유로 저장소와 조회 화면까지 자동 재설계하지 않는다.
    
*   Next.js 대시보드는 뒤로 미룰 수 있다. 테스트·가상 추적·재현성을 우선한다.
    
*   무료 티어는 목표로 유지하되, 원본·장기 시계열·검증 로그의 실제 용량을 측정한다. 월 0원을 보장 조건으로 쓰지 않는다.
    

## 8. 단계별 완료 기준

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| Phase 0 | 데이터 계약과 실패 테스트 | 분할 반례·공란 응답·날짜 오류·결측·미래 혼입·단위 문제를 재현하고 처리 규칙 확정 |
| Phase 1 | KRX 수집·초기 백필·키움 마스터 보완 | 유효 원천과 상태 기록 재현, 최초 관측/상장일 구분, 코드 연결 검증 |
| Phase 2 | 가격·거래대금 Scanner | 동일 입력·전략 버전에서 동일 결과, 데이터 불완전 시 보류, 0개 알림 허용 |
| Phase 3 | 가상 포트폴리오와 텔레그램 | 신호 이후 체결, 현금·중복 진입·비용 가정 반영, 발송 중복 방지 |
| Phase 4 | 전향적 관측·순설정 실험 | 운영 품질과 전략별 가격성과 분리 평가, 사전 규칙 유지 |
| Phase 5 | 계속/단순화/중단 결정 | 기준 전략 대비 추가 가치·낙폭·비용 민감도·데이터 한계를 함께 평가 |

좌수 변동 종목 수, 일평균 신호 건수, 연속 등장 월간 횟수만으로 Go/No-Go를 정하지 않는다. 순설정 기능이 검증되지 않거나 도움이 없으면 해당 기능을 축소한다. 단순 기준 전략과 비교해 추가 가치가 없으면 복잡한 신호를 유지하지 않는다.

## 9. 개발 명세에 고정할 원칙

Spec Kit의 `spec.md`와 프로젝트 헌장에 다음을 명시한다.

1.  투자·시장 데이터 원천은 키움·KRX로 제한한다.
    
2.  미확보 필드와 상품 속성을 추정해 확정값으로 채우지 않는다.
    
3.  기능별 데이터 적격성 게이트를 두고, 일부 기능의 보류를 전체 수집 중단과 분리한다.
    
4.  가격성과·가정 비용 차감 가격성과·총수익률·실거래 손익을 구분한다.
    
5.  미래 정보 사용, 당일 마감 후 신호의 당일 종가 체결, 결과 확인 후 규칙 변경을 금지한다.
    
6.  신호·입력·전략·비용 가정·의사결정 버전을 저장한다.
    
7.  순위 상위나 신호 중첩만으로 매수 승인을 만들지 않는다.
    
8.  핵심 오류는 실패 테스트부터 작성하고 실행 증거로 수정 여부를 판정한다.
    

## 10. 다음 행동 하나

**Phase 0을 ‘키움·KRX 데이터 계약 + 실패 테스트 패키지’로 작성한다.** KRX·키움 단위·날짜·현재 상장일을 검증하고, 분할·결측·미래 혼입 반례를 고정한다. 순설정 기능의 불확실성이 남아도 가격·거래대금 Scanner와 전향적 가상 추적이 진행될 수 있도록 기능별 승인 조건을 분리한다.
