## 1. 제안과 성공의 의미

권장 방향은 **중기 모멘텀에 기반한 설명 가능한 후보 선정 규칙 한 가지를 먼저 검증**하는 것이다. 최근 상승 순위를 미래 수익 예측으로 표현하거나, ETF가 자기 추적지수보다 조금 더 오른 사실을 시장 전체에 대한 초과수익으로 해석하지 않는다.

개발 산출물과 투자 성과의 성공을 구분한다.

- 개발 성공: 같은 데이터·기준시각·전략 버전이면 같은 후보와 성과가 재현되고, 결측·오래된 데이터·미래 정보 사용을 차단한다.
- 연구 성공: 사전 고정한 벤치마크와 평가 기간에서 비용 차감 후 초과수익과 위험 기준을 충족한다.
- 연구 실패도 유효한 결과다. 기준 미달이면 추천 기능 승격을 보류하고, 실패 결과와 실험 이력을 보존한다.
- 후보가 없거나 데이터가 부족한 주에는 `후보 없음` 또는 `데이터 부족으로 생성 보류`를 제공한다.
- `초과수익 목표 실험 후보`로 표시하고, 보장 수익률·근거 없는 성공확률·개별 투자자의 적합성 판단은 제공하지 않는다.

## 3. 첫 출시 범위 제안

### 3.1 포함 범위

- 한국 주식에 투자하는 국내 상장 일반 주식형 ETF. 국가·자산군·레버리지·인버스 여부가 확인된 종목만 포함한다.
- 적격 유형은 광역 시장지수·섹터·업종·테마·스타일(배당·가치·성장 등) 패시브 ETF로 제안한다. 다음은 수익 구조나 비교 기준이 달라 v1에서 제외한다.
  - 커버드콜·옵션 결합형: 분배금 비중이 크고 상승 참여가 제한돼 가격 모멘텀과 시장 초과 비교가 왜곡된다.
  - 합성(스왑) ETF와 주식·채권 혼합형: 자산군 판정과 총수익 대조 계약이 별도로 필요하다.
  - 액티브 ETF: 비교지수와 운용 재량이 섞여 동일 추적지수 그룹 판정이 어렵다. 포함 여부는 D1에서 함께 결정한다.
  - 유형 판정 근거(공식 상품 분류·투자설명서)와 판정 버전을 기록한다. 이름의 키워드만으로 판정하지 않는다.
- 시장·섹터 ETF를 대상으로 한 주간 최대 3개 후보와 선정 이유, 위험 지표, 제외 이유.
- 분배금·기업행동이 처리된 총수익률 시계열과 당시 종목군에 기반한 평가.
- 월 1회 리밸런싱하는 동일 비중 가상 포트폴리오와 시장 벤치마크 비교.
- 전략·데이터·추천 시점·가상 체결·이후 성과를 연결하는 감사 기록.

### 3.2 후속 범위

- 미국 상장 ETF 및 해외자산에 투자하는 국내 상장 ETF. 통화·환율·거래일·세금 계약을 따로 확정한 뒤 확대한다.
- 과매도 회복 전략, 펀더멘털·산업 리서치, 순설정 추정 결합.
- 구성종목 중복을 이용한 정밀 분산 규칙. 보유 내역의 당시 시점 자료가 확보돼야 한다.
- 개인별 투자금·보유자산·위험 선호를 반영하는 맞춤 추천.

자동주문, 실계좌 연동, 레버리지·인버스·ETN, 생성형 AI의 재량적 종목 선택은 초기 범위에서 제외한다. 초기 화면의 설명은 계산값에 연결되는 정형 문구로 충분하다.

| 매매 규칙 | 월간 리밸런싱 때 목표 비중으로 맞춤. 초기 전략에 별도 손절·장중 매매를 추가하지 않음 |
| 위험 평가 | 최대낙폭·변동성·섹터 집중·거래비용을 함께 공개. 손실 상한을 보장하지 않음 |

시장지수는 투자자의 거래비용을 차감하지 않는 이론적 기준이고, 전략은 ETF 내부 보수가 반영된 가격·분배금과 투자자 거래비용을 사용한다. 이 차이를 명시하고 실제 추종 ETF 비교에서도 같은 거래비용 모델을 적용한다. 거래비용 차감 후 세전 결과를 1차 연구 기준으로 하며, 실전 사용 전 계좌 유형별 세금 검토를 별도 수행한다.

수익률은 동일 시작·종료 시점과 통화로 비교한다.

```text
기간 초과수익(%p) = (전략 누적 총수익률 - 시장 누적 총수익률) × 100
CAGR 차이(%p) = (전략 연환산 복리수익률 - 시장 연환산 복리수익률) × 100
```

여기서 초과수익은 수익률 차이이며 위험을 보정한 알파와 동일하지 않다. 주간 추천별 1·3·6개월 후 성과는 진단 지표로 기록하고, 출시 판단의 1차 단위는 매매·현금·비용이 모두 포함된 가상 포트폴리오다.

## 5. 데이터 확보와 품질 계약

현재 KRX 종가·추적지수·거래대금 자료는 탐색 신호의 재사용 후보지만, 그 자체로 추천 성과용 총수익 데이터가 완성된 것은 아니다. 데이터 제공 범위·조회 가능 기간·사용 조건은 실측과 공식 문서로 확인한다.

| 필요한 자료 | 필요한 이유 | 확보·검증 조건 |
| --- | --- | --- |
| ETF 원시 가격과 거래대금 | 체결 가정·유동성·이상치 검사 | 거래일 연속성, 거래 정지, 통화·단위·종목 식별자 확인 |
| 분배금·분할·병합 등 기업행동 또는 검증 가능한 총수익 시계열 | 분배락을 손실로 오인하지 않고 총수익 계산 | 조정 방식·반영 시점 확인. 이미 조정된 수익률에 분배금을 다시 더하지 않음 |
| KOSPI 200 총수익지수 | 시장 비교 | ETF와 동일 기간·통화·거래일 정렬 및 지수 버전 확인 |
| 과거 상장·상장폐지·투자 대상·섹터 분류 | 생존편향 방지와 적격 종목군 복원 | 해당 판단일에 존재하고 알려져 있던 종목·분류로 구성 |
| 과거 개장 가격 또는 체결 대용 자료 | 다음 거래일 체결 재현 | 사용 가격과 공표시각 확인. 개장 가격이 없으면 다음 종가 방식의 별도 실험으로 구분 |
| 데이터 가용 시각과 원천 정정 이력 | 미래 정보 사용·사후 정정 영향 파악 | `effective_at`, `available_at`, `retrieved_at`을 구분하고 원천 버전을 고정 |

모든 자료는 출처, 수집 시각, 적용일, 원천 해시, 정규화 버전, 조정 방식, 이용 조건을 기록한다. 과거 데이터가 실제로 언제 이용 가능했는지 확인하지 못하면 보수적 지연 가정을 명시하고, 당시 정보가 완전히 복원됐다는 주장을 하지 않는다.

데이터 예외 처리는 다음과 같이 고정한다.

- 필수 시계열 결측·분류 불명·해결되지 않은 기업행동은 해당 ETF를 제외하고 이유를 기록한다. 벤치마크 결측이나 거래일 정합성 실패는 해당 평가 실행 전체를 차단한다.
- 현존 ETF만으로 수행한 예비 검증은 `현재 생존 종목 한정`으로 표시한다. 정식 성과 게이트의 근거로 사용하지 않는다.
- 상장폐지 종목을 0원 또는 마지막 가격으로 임의 처리하지 않는다. 청산·합병·지급 자료와 당시 가용 시점에 맞는 처리 규칙이 없으면 연구 승격을 보류한다.
- 정정된 원천으로 재계산할 때 새 데이터 버전을 만든다. 과거 추천·원래 성과와 대체해 덮어쓰지 않는다.
- 외부 데이터 사용 조건·비용·자격 증명·운영 쓰기가 필요한 경우 정확한 대상과 대안을 제시해 별도 승인받는다.

## 6. 초기 후보 선정 규칙 제안

전략 이름은 `kr-equity-momentum-v1`로 제안한다. 순위 산식과 필터는 검증 전에 고정하고, 결과를 보고 가중치·기간을 바꾸면 새 실험 버전으로 기록한다.

### 6.1 적격성 필터

1. 판단일 당시 국내 주식형 일반 ETF로 확인되고 상장·거래 가능해야 한다.
2. 총수익 시계열은 최소 274개 연속 거래일 관측값을 확보한다.
3. 직전 60거래일 평균 거래대금은 10억 원 이상으로 제안한다. 장부상 거래대금만으로 체결 가능성을 보장하지 않으므로 실제 투자금·호가 점검은 운영 전 별도 확인한다.
4. 필수 결측·가격 정체 의심·기업행동 미해결·분류 불명은 제외한다.
5. 거래 정지·상장폐지 예정 등 제외 정보는 판단 시점까지 알려진 것만 사용한다.

### 6.2 점수와 후보 선정

거래일 순번 `t`와 총수익지수 `TRI`를 사용하고 최근 21거래일은 모멘텀 계산에서 제외한다.

```text
M6(t)  = TRI(t-21) / TRI(t-147) - 1
M12(t) = TRI(t-21) / TRI(t-273) - 1
score(t) = 0.5 × percentile(M6) + 0.5 × percentile(M12)
```

- `percentile`은 같은 판단일의 전체 적격 ETF 안에서 계산한다. 적격 수 `n > 1`이면 작은 모멘텀부터 매긴 평균 등수 `r`에 대해 `(r - 1) / (n - 1)`을 사용하고, 1개뿐이면 0.5로 둔다.
- `M6 > 0`과 `M12 > 0`을 모두 만족한 ETF를 `score` 내림차순, 동점이면 종목 식별자 오름차순으로 정렬한다.
- 중복 제한 그룹은 판단일 당시의 확인된 섹터·업종 분류를 기본 키로 제안한다. 광역 시장지수 ETF(KOSPI 200·KOSPI·KRX 300 등)는 하나의 `broad_market` 그룹으로 묶는다. 같은 그룹에서는 1개만 선택하고, 서로 다른 그룹에서 최대 3개를 고른다.
  - 근거: 국내 섹터 ETF는 운용사마다 다른 지수(예: 같은 반도체 업종의 서로 다른 지수 제공자)를 추적하므로 동일 추적지수 기준만으로는 같은 섹터 3개가 선택될 수 있다.
  - 당시 분류를 확보하지 못한 ETF는 동일 추적지수 그룹을 대체 키로 쓰고, 대체 키 사용 여부를 후보에 기록한다. 종목코드·이름만으로 그룹을 추정하지 않는다.
- 이 그룹 제한도 섹터 간 구성종목 중복(예: 대형주 비중이 큰 테마 ETF)을 완전히 해소하지 않는다. 한계를 보고서에 표시한다.
- 60거래일 변동성, 최근 1년 최대낙폭, 거래대금, 시장 대비 과거 수익률을 위험·설명 항목으로 제공한다. 초기 점수에 추가 가중치를 섞지 않는다.
- 거래대금 급증과 순설정 추정은 초기 추천 점수에 넣지 않는다. 모멘텀 규칙의 검증 후 별도 증분 실험으로만 평가한다.

이 규칙은 검증할 가설이며 국내 ETF의 미래 초과수익을 입증한 결과가 아니다. 후보 선정 산식과 시장 벤치마크 비교는 별개이며, 과거 강세를 근거로 향후 수익률 숫자를 만들어 제시하지 않는다.

## 7. 시점과 가상 체결 계약

- `signal_as_of`는 신호에 사용한 마지막 시장 기준일이다. `generated_at`과 모든 입력의 `available_at`도 별도 저장한다.
- 금요일 종가로 계산했다는 이유만으로 금요일 종가에 매수한 것으로 처리하지 않는다.
- 기본 체결은 모든 입력이 가용해지고 후보가 생성된 뒤의 첫 거래일 개장으로 한다. 다음 거래일 개장 뒤에 자료가 완성되면 그 개장 체결을 사용할 수 없다.
- 현재 운영 경로는 기준일 `T`의 KRX 자료를 다음 거래일 09:30 KST timer(`ops/systemd/etf-kr-daily-dispatch.timer`)로 수집하므로, 09:00 개장 전에는 후보가 완성되지 않는다. 회사 PC가 근무시간에만 가동되므로 실제 수집은 더 늦어질 수 있다. 따라서 v1 기본 체결은 **`T` 다음 둘째 거래일 개장**으로 제안한다.
- 백테스트도 같은 지연을 적용한다. 백테스트만 `T+1` 개장 체결을 쓰면 G4 가상운영과 체결 시점이 달라 대조가 성립하지 않는다. KRX 공식 제공 시각은 ER-1에서 확인하고, 더 이른 가용이 확인되더라도 운영 경로가 실제로 그 시각에 후보를 만들 수 있을 때만 체결 지연을 줄인다. 이때는 새 실행 모델 버전으로 기록한다.
- 개장 체결이 불가능하거나 가격 자료가 없으면 대체 체결 규칙을 사전 확정하고 실험 버전을 분리한다. 실제 체결 시점까지 가상 포트폴리오는 이전 보유·현금을 유지한다.
- 매수·매도 각각 체결대금의 0.15%를 수수료·스프레드·슬리피지 합산 비용의 초기 제안값으로 사용하고 0.30%로 스트레스 평가한다. 실측 비용으로 확정하기 전에는 가정임을 표시한다.
- ETF 내부 보수는 가격·총수익 자료에 반영된 범위를 확인하고 중복 차감하지 않는다. 보유분 분배금은 정해진 재투자 방식으로 한 번만 반영한다.
- 초기 연구 포트폴리오는 수익률 비교를 위한 소수 수량을 허용한다. 매수 비용을 포함한 현금 제약을 지켜 현금·순자산이 음수가 되지 않도록 수량을 계산한다. 실제 투자금·정수 수량·최소 수수료가 적용되는 체결 검증은 운영 전환 전에 추가한다.
- 총수익지수는 신호·평가에 사용하고 매매는 원시 가격·수량·현금으로 재현한다. 월중 분배금 처리와 월간 총수익 대조가 일치해야 한다.
- 거래 정지·폐지·기업행동이 보유 중 발생하는 경우의 청산·평가 규칙도 데이터를 통해 고정한다. 불가능한 체결을 성공으로 가정하지 않는다.

## 8. 성과 검증과 승격 게이트 제안

### 8.1 검증 데이터 분리

1. 원천 확보 목표는 가능한 경우 7년 이상으로 잡되, 기간보다 당시 종목군·기업행동·총수익의 신뢰성을 우선한다.
2. 273거래일 준비 구간, 최소 24개월의 개발 구간, 이후 최소 36개월의 시간 순서 평가 구간을 분리한다. 전체 3~5년 자료만으로는 이 최소 구간을 모두 충족하지 못할 수 있다.
3. 평가 구간의 마지막 12개월은 최종 보류 구간으로 잠근다. 앞선 평가 결과를 보고 규칙을 변경하면 해당 평가 구간도 개발에 사용한 것으로 기록한다.
4. 시간 순서대로 평가 구간을 진행하고 학습·선택에 미래 시점을 섞지 않는다. 최종 보류 구간은 규칙·비용·벤치마크를 고정한 뒤 한 번 평가한다.
5. 필요한 기간·시장 국면이 확보되지 않으면 예비 결과까지만 제시한다. 자료가 짧다는 이유로 출시 기준을 사후 완화하지 않는다.
6. 과거 최종 보류 구간은 코드로는 잠글 수 있지만, 설계자와 에이전트가 해당 기간의 시장 흐름(주도 섹터·지수 급등락)을 이미 알고 있어 완전한 표본 외 검증이 아니다. 산식·필터를 이 지식으로 고르지 않았다는 근거(설계 결정 기록과 일시)를 남기고, 진정한 표본 외 증거는 G4 이후의 전진 관측으로 본다. 전진 관측 성과는 G4 종료 뒤에도 같은 형식으로 계속 누적한다.

### 8.2 비교군과 지표

- 비교군: 시장 총수익지수, 사전 선정 시장 추종 ETF 매수 후 보유, 같은 적격 종목군의 동일 비중 월간 리밸런싱.
- 핵심 지표: 비용 차감 후 CAGR 차이, 누적 초과수익, 최대낙폭, 변동성, 거래 회전율, 비용 기여도, 현금 비중.
- 안정성 지표: 연도·시장 국면별 성과, 6개월 보유 구간의 초과수익 비율, 특정 ETF·섹터에 대한 수익 집중도.
- 6개월 수익률이 겹치는 주간 관측치를 독립 표본 수로 세지 않는다. 비중복 구간 결과와 표본 수를 함께 제시한다.
- 시계열 의존성을 고려한 신뢰구간과 민감도를 보고하고, 표본 수가 적으면 통계적 우위가 확정되지 않았다고 표시한다.
- 시도한 산식·필터·비용 가정의 전체 목록을 보존한다. 성과가 좋은 실험만 선택해 보고하지 않는다.

### 8.3 게이트

| 게이트 | 통과 조건 제안 | 실패 시 처리 |
| --- | --- | --- |
| G0 범위·계약 | 14절 D1~D5 결정, 데이터·벤치마크·체결·비용·기간 고정 | 초안 보완까지만 진행 |
| G1 데이터 | 당시 종목군·기업행동·총수익·시점·벤치마크 대조 통과 | 부족 자료와 예비 결과의 한계 기록 |
| G2 재현성 | 같은 입력·버전의 후보·체결·성과 일치, 미래 정보 참조 검사 통과 | 결함 수정 후 같은 게이트 재검증 |
| G3 연구 | 평가 구간 전체와 최종 12개월에서 각각 비용 차감 후 CAGR 차이 양수, 전체 평가 최대낙폭이 시장보다 5%p 이상 악화되지 않음, 비용 2배에서도 전체 평가 CAGR 차이 양수 | 실험 유지·보완·폐기 결정. 추천 운영 승격 보류 |
| G4 가상운영 | 8~12주 동안 시점·재현성·누락·체결 가정 대조, 해결되지 않은 중대 오류 0건 | 운영 결함 수정. 이 기간만으로 수익성 입증 불가 |
| G5 제한 공개 | M6 종료·R2 검토, G0~G4 결과 검토, 인증·RLS·되돌리기 확인, D5 공개 대상 확인 및 운영 노출 승인 | 로컬 연구 경로 유지 |

G3의 수치도 사용자 검토 대상인 제안값이다. 특히 최종 12개월 조건은 3개 내외 ETF의 월간 보유라는 구조상 우연의 영향이 크다. 좋은 전략도 한 해 시장에 뒤질 수 있고, 반대로 우연히 통과할 수도 있으므로 이 조건만으로 승격·폐기를 판단하지 않고 평가 구간 전체·국면별 결과와 함께 본다.

공개 범위가 사용자 본인을 넘어 제3자(가족·지인 포함 불특정 또는 유료 이용자)로 확대되면 투자 판단 정보 제공에 해당하는지 자본시장법상 투자자문·유사투자자문 관련 검토가 필요하다. 이 계획은 본인 사용을 전제로 하며, 제3자 공개는 G5에서 별도 검토·승인 전까지 범위 밖이다. 통과하더라도 미래 수익이나 통계적 유의성을 보장하지 않는다. 충분한 표본·국면별 일관성·신뢰구간을 함께 검토하고, 신뢰구간이 0을 포함하면 `통계적 우위 미확정`을 유지한다.

## 9. 출력과 감사 기록

후보 보고서는 다음 정보를 제공한다.

- 기준일·생성시각·전략 버전·데이터 버전·시장 벤치마크.
- 후보명·종목 식별자·순위·모멘텀 값·선정 이유·위험 지표.
- 후보 없음 또는 제외·생성 보류 사유.
- 과거 검증과 추천 이후 실제 관측 결과를 분리한 성과.
- 분배금·비용·체결·세금 가정과 데이터 한계.

저장 계약의 최소 항목은 다음과 같다. 테이블 생성은 후속 승인 대상이며 초기에는 동일 구조의 로컬 산출물로 검증한다.

| 객체 | 최소 필드 |
| --- | --- |
| 연구 실행 | `run_id`, `strategy_version`, `universe_version`, `data_version`, `input_hash`, `signal_as_of`, `inputs_available_at`, `generated_at`, `benchmark_id`, `cost_model_version`, `status` |
| 후보 | `run_id`, `instrument_id`, `rank`, `score`, `momentum_6m`, `momentum_12m`, `group_key`, `group_key_source`, `reason_codes`, `risk_metrics` |
| 가상 거래 | `portfolio_id`, `run_id`, `eligible_after`, `executed_at`, `raw_price`, `quantity`, `cost`, `execution_model_version` |
| 성과 | `portfolio_id`, `valuation_date`, `nav`, `cash`, `benchmark_value`, `drawdown`, `return_basis`, `data_version` |
| 감사·제외 기록 | `run_id`, `instrument_id`, `rule_id`, `reason_code`, `input_hash` |

연구 결과는 기존 `signal_run`·`signal_daily`와 다른 전략·저장 계약으로 관리한다. 재실행은 같은 입력으로 중복 후보·중복 가상 거래를 만들지 않아야 한다. 새 원천 정정은 새 실행으로 연결하고 기존 실행을 보존한다.

## 11. 단계별 개발 작업과 완료 조건

이 절의 체크박스는 계획된 산출물이며 실제 진행·완료 상태는 `NEXT.md`에서 관리한다. 구현 코드를 바로 작성할 수 있는 상세 실행안은 G0와 데이터 실측 뒤 작성한다.

### ER-0. 범위·성공 기준 확정 — 1~2개발일

- [ ] 14절 D1~D5의 선택과 근거를 기록하고 v2.2 제외 범위와 확장 계약을 정합화한다.
- [ ] 벤치마크·비용·현금·리밸런싱·위험·최종 보류 구간을 하나의 실험 명세로 고정한다.
- [ ] 새 기능 착수 시 Spec Kit constitution 적용 여부를 재판단하고 중복 정본을 만들지 않는다.

**완료 조건:** G0 통과. 아직 확보하지 않은 데이터가 확보된 것으로 표시되지 않으며 운영 승인을 범위 결정과 구분한다.

### ER-1. 데이터 확보 가능성 조사 — 3~5개발일

- [ ] 기존 자료의 실제 기간·결측·기업행동·상장폐지·분류 범위를 읽기 전용으로 조사한다.
- [ ] 원천별 공식 문서·이용 조건과 표본 데이터를 대조하고 추가 원천·비용·권한 필요 여부를 기록한다.
- [ ] 분배금 발생·분할·상장폐지·거래 정지 사례의 작은 표본으로 총수익·체결 재현 가능성을 확인한다.
- [ ] 8.1절 구간을 충족하는지 보고하고, 미충족 시 예비 검증 범위 또는 추가 자료 확보안을 제시한다.

**완료 조건:** 타당성 보고서와 데이터 계약, G1 통과 또는 구체적 차단 목록. 데이터 확보가 불가능하면 이 단계에서 범위를 줄이거나 보류한다.

### ER-2. 후보 계산과 시점 계약 — 2~3개발일

- [ ] 확정 계약을 입력·출력 타입과 작은 fixture로 표현한다.
- [ ] 기간 경계·미래 정보 차단·동률·그룹 중복·후보 없음 테스트를 먼저 실패시킨 뒤 최소 구현한다.
- [ ] 전략·원천 해시·제외 사유를 포함한 로컬 후보 산출물을 만든다.

**완료 조건:** 같은 입력·버전의 동일 결과, 정보 가용 시각 이후에만 후보 생성, 기존 P0 신호 회귀 없음.

### ER-3. 가상 포트폴리오와 성과 검증 — 3~5개발일

- [ ] 다음 거래일 체결·월간 리밸런싱·현금·비용·기업행동·보유 중 폐지를 테스트부터 구현한다.
- [ ] 시장·추종 ETF·동일 비중 비교군과 시간 분할 평가를 같은 CLI 산출물로 생성한다.
- [ ] 개발 구간에서 코드·계약을 검토한 뒤 규칙을 동결하고 평가 구간·최종 보류 구간을 실행한다.
- [ ] 모든 실험과 실패 결과를 기록하고 독립 리뷰로 누수·생존편향·비용 이중 계산을 점검한다.

**완료 조건:** G2 재현성 통과와 G3 통과/실패 보고서. 성과 실패를 코드 미완성으로 숨기지 않는다.

### ER-4. 가상운영·연구 보고 — 개발 2~3일 + 관측 8~12주

- [ ] G3 검토 뒤 새 주간 후보와 월간 가상 거래를 시점 고정으로 기록한다.
- [ ] 백테스트 경로와 일별 가상운영 경로의 후보·수익·비용 계산이 일치하는지 대조한다.
- [ ] 생성 누락·지연·정정·중복·실행 실패의 보류 및 재개 결과를 기록한다.

**완료 조건:** G4 통과. 중기 성과는 계속 누적하며 짧은 가상운영을 장기 초과수익의 증거로 사용하지 않는다.

### ER-5. 제한 공개와 운영 전환 — 2~3개발일 + 승인 대기

- [ ] G5 선행조건을 확인하고 인증 화면·읽기 권한·기본 `off` 기능 플래그의 별도 실행안을 작성한다.
- [ ] 추천 근거·위험·데이터 부족·성과 미확정을 포함한 화면과 운영 되돌리기를 검증한다.
- [ ] migration·운영 플래그·예약 실행·Telegram 발송은 각각 범위와 되돌리기를 제시해 승인받는다.

**완료 조건:** 승인된 범위에 한해 공개하고 기존 KR·US 경로의 수집·저장·보고를 방해하지 않는다.

개발 규모의 초기 추정은 **13~21개발일 + 8~12주 가상운영**이다. 데이터 계약·외부 원천 확보·승인 대기·M6 종료는 포함하지 않은 상대적 추정이며 확정 일정이 아니다. 병렬화는 파일과 선행 산출물이 분리된 조사·리뷰에 한정하고 구현 단계의 의존성을 건너뛰지 않는다.

## 12. 검증 시나리오와 실행 명령

| 영역 | 필수 검증 시나리오 |
| --- | --- |
| 총수익 | 가격 100→95, 분배금 5인 단순 사례에서 비용 전 총수익 0%. 조정 시계열에 분배금 중복 가산 금지 |
| 기업행동 | 1:2 분할에서 수량 2배·원시 가격 절반으로 경제적 가치 보존 |

| 종목군 | 당시 존재한 폐지 종목 포함, 미래 상장 종목 제외. 커버드콜·합성·혼합형 제외 사유 기록. 현재 생존 종목 한정 평가의 정식 게이트 통과 금지 |
| 점수 | 274개 관측 경계, 양의 모멘텀 필터, 평균 동률 순위, 단일 종목, 최대 3개·같은 섹터 분류 또는 `broad_market` 중복 제거, 분류 부재 시 추적지수 대체 키 기록 |
| 포트폴리오 | 후보 1개일 때 1/3 투자·2/3 현금. 매도·매수 각각 비용 차감. 월간 교체와 분배금 회계 대조. 월중 주간 후보 변화로 거래가 생기지 않음 |
| 지표 | 시장과 전략의 동일 기간·통화·수익 기준, 비용 후 성과, 최대낙폭 부호와 계산 |
| 감사 | 같은 입력 재실행의 동일 결과, 원천 정정 시 새 버전 생성·기존 결과 보존 |
| 회귀·장애 | 추천 계산 실패·플래그 `off`가 기존 KR·US 보고에 영향 없음, 불완전 입력으로 후보 공개 금지 |

구현 시 단계별 대상 검증 후 저장소 전체 게이트를 실행한다.

```bash
npx vitest run test/recommendations
npm test
npx tsc --noEmit
npm run lint
npm run build
npm run continuity:check
git diff --check
```

위 명령은 **향후 구현 검증 계획**이며 이번 초안 작성에서 통과했다는 기록이 아니다. 문서 작성 자체는 링크·계약 일관성·산식·일정 합계·변경 범위·diff·연속성 검사로 확인한다.

## 13. 중단·축소·재개 기준

- 총수익·당시 종목군·벤치마크가 확보되지 않으면 정식 추천 성과 검증을 보류한다. 가격 기반 탐색과 제한된 예비 연구만 제공한다.
- G3 기준 미달이면 전략 유지·수정·폐기를 문서로 결정한다. 수정은 새 버전과 새 평가 구간 계획을 요구한다.
- 특정 ETF·섹터·상승장에만 성과가 집중되면 범위 제한과 근거를 제시하고 승격을 재검토한다.
- 운영 데이터 쓰기·자격 증명·권한·비용·발송·timer 변경은 기존 상시 승인 범위에 포함시키지 않는다.
- 기존 입력 정확성 결함이 발견되면 추천 평가를 차단하고 원천 문제를 먼저 해결한다.
- 출시 후 플래그를 끄면 새 후보 생성·공개·발송을 중지하되, 기존 감사 기록과 가상 포트폴리오의 미평가 노출은 보존한다.
